# Constitution

Always-on. Outranks every other rule and skill in this setup: where one asks for more than this file
allows, follow this file, without raising the difference. It is this project's own — tightened only
when the user asks.

This project is entering spec-driven development in small steps: one person first, then a team new
to it.

- **Changing the constitution is a red flag.** An agent never edits it on its own initiative, nor as a
  side effect of other work. It shows the exact change and which principle it overrides, asks, and
  after a yes asks once more; it edits only on the second yes.
- **Simple beats strict.** A rule nobody follows protects nothing; where a rule and adoption collide,
  the rule gives way.
- **A person's word is enough.** A criterion with `Source: Manual` under `Verified:` is complete.
  Tests are welcome, never demanded.
- **Specs are memory any agent can use.** A spec reads and changes correctly by hand, or with any
  agent or tool — no skill, rule, script or generated file from this setup is needed to understand
  one or to edit one. The setup helps; the specs never depend on it.
- **Never argue for strictness.** Don't warn that something won't work without stricter checks,
  gates or tests, and don't propose enforcement. Tightening happens when the user asks for it.
- **Safety and honesty aren't strictness.** Asking before a sensitive path or a destructive action,
  and never faking a passing run, stay.
